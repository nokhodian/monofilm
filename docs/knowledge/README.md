# Monofilm knowledge base: directing AI-generated film

A shared, growing body of knowledge about making films with AI video models: how to prompt, direct, keep characters and places consistent, continue a story from clip to clip, and check the result. It exists so that Monofilm (and any agent working on it) improves from evidence and not from guesses.

Everything here is plain files in git. Any agent can add to it. `npm run kb:check` must pass before you commit.

## Layout

```
docs/knowledge/
  README.md              this file: the rules and the schema
  sources/<cluster>.jsonl   one JSON object per line: one source that was really read
  practices/<cluster>.jsonl one JSON object per line: one actionable practice, backed by sources
  models/<model>.md      one profile per video/image model (capabilities, controls, quirks, prompt dialect)
  playbook/*.md          the distilled guides, written from the practices (human reading)
  index.json             generated by `npm run kb:build`; do not edit by hand
```

A **cluster** is a topic area with a short prefix used in ids:

| prefix | cluster | covers |
|---|---|---|
| `pm` | prompting-models | official prompting guides and dialects per model |
| `cin` | cinematography | shot language, camera, lighting, pacing, editing grammar for AI video |
| `chr` | character-consistency | references, sheets, LoRAs, identity-preserving methods, in tools and papers |
| `scn` | scene-continuity | places, objects, keyframes, first/last frame, extension, chaining clips |
| `sty` | story-structure | narrative for short AI films, beats per clip, script to shot list, LLM screenwriting |
| `res` | research-papers | long-video generation, consistency, evaluation benchmarks |
| `phy` | physics-failures | physics, counts, hands, liquids, morphing, text; mitigations |
| `aud` | audio-dialogue | native audio, dialogue, lip-sync, voice consistency, sound design |
| `wf` | workflows | practitioner pipelines, case studies, post-production, iteration habits, cost |
| `qa` | evaluation-agents | automatic review of video, prompt rewriting, agentic film pipelines, safety, provenance, rights |
| `ani` | animation-style | stop motion, cartoon, style locking, animation principles, children's content |

New clusters are allowed: pick a unique short prefix and add a row above.

## The rules (read these first)

1. **Only add a source you really opened.** Never write a source or a claim from memory or from a title. If you could only see a search snippet, set `access` to `search-summary`. If you cannot reach it, do not add it.
2. **Paraphrase.** No long quotes (at most one short phrase, in quotation marks). Claims are short, specific and checkable (numbers, limits, names, settings), not general praise.
3. **Say how strong the evidence is.** A vendor's own blog is `vendor`. A single user's experience is `anecdotal`. A measured comparison or an ablation in a paper is `measured`.
4. **Practices must cite sources.** A practice with no source is a guess: put it in `models/` notes as `unverified`, or leave it out.
5. **One URL, one source.** The checker rejects duplicates (after removing `www.`, tracking parameters and a trailing slash). Search before you add.
6. **Disagreement is knowledge.** If two sources conflict, keep both and link the practices with `conflicts`.
7. **Say what it means for Monofilm.** Every practice has a `monofilm` field saying whether the studio already does it, and where.
8. **Never put secrets, private data or copied paywalled text here.**

## Source record (`sources/<cluster>.jsonl`, one line each)

```json
{"id":"chr-001","url":"https://example.com/page","title":"Page title","publisher":"Who made it","published":"2026-03","type":"official-doc","tags":["character","reference-images"],"models":["veo-3.1"],"claims":["Accepts up to three reference images of one character.","A clean neutral reference works better than a posed scene."],"quality":"primary","access":"full","retrieved":"2026-11-08","notes":"Anything a later reader should know."}
```

| field | rules |
|---|---|
| `id` | `<prefix>-NNN`, unique across the whole knowledge base |
| `url` | `https://...`, one per source |
| `title`, `publisher` | text; publisher is the organisation or author |
| `published` | `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; empty string if unknown |
| `type` | `official-doc`, `paper`, `repo`, `tutorial`, `blog`, `forum`, `video`, `case-study`, `dataset`, `news`, `spec` |
| `tags` | short lowercase words |
| `models` | model ids this source is about (`veo-3.1`, `sora-2`, `kling-2.5`, `runway-gen-4`, `wan-2.2`, `minimax-hailuo`, `seedance`, `ltx-video`, `flux-kontext`, ...); `[]` if general |
| `claims` | 1 to 6 strings, each at most 240 characters |
| `quality` | `primary` (the maker or the authors), `secondary` (a careful third party), `anecdotal` |
| `access` | `full`, `partial`, `abstract`, `search-summary` |
| `retrieved` | `YYYY-MM-DD`, the day you read it |
| `notes` | optional |

## Practice record (`practices/<cluster>.jsonl`, one line each)

```json
{"id":"chr-p-001","cluster":"character-consistency","title":"Anchor every clip with the same clean reference","rule":"Give the generator the same approved reference picture of each character in every clip, and do not describe the character again in words.","why":"Words and picture can disagree and the model flips between them.","how":"Reference first, one short identity phrase at most, shot-specific words after it.","applies_to":["all"],"stage":"prompt","evidence":["chr-001","chr-014"],"strength":"multi-source","conflicts":[],"monofilm":{"status":"done","where":"public/js/wizard-model.js composeClip (film.pictures)","idea":""},"contributor":"agent-name","date":"2026-11-08"}
```

| field | rules |
|---|---|
| `id` | `<prefix>-p-NNN`, unique |
| `cluster` | the cluster name |
| `title` | short |
| `rule` | one imperative sentence a person or an agent can follow |
| `why` | the mechanism or the evidence in one or two sentences |
| `how` | how to do it, with an example prompt fragment if useful |
| `applies_to` | `["all"]` or model ids |
| `stage` | `plan`, `picture`, `prompt`, `generation`, `review`, `assembly`, `audio`, `policy` |
| `evidence` | one or more source ids that exist |
| `strength` | `measured`, `multi-source`, `single-source`, `vendor`, `anecdotal` |
| `conflicts` | practice ids this disagrees with |
| `monofilm` | `{status: none/partial/done, where: file or feature, idea: what to build if not done}` |
| `contributor`, `date` | who and when |

## Model profile (`models/<model>.md`)

Front matter then sections. Keep it factual and sourced (source ids in brackets).

```
---
model: veo-3.1
maker: Google
kind: video
updated: 2026-11-08
---
## Controls          (what inputs it takes: text, first/last frame, references, audio, length, resolution)
## Prompt dialect    (what wording works, order, length)
## Known weaknesses  (with source ids)
## Consistency tools (how it keeps characters and places)
## Cost and limits
```

## How to contribute

1. Run `npm run kb:check` to see the current counts.
2. Search the existing sources for your topic (`grep -il "keyword" docs/knowledge/sources/*.jsonl`). Do not duplicate.
3. Read real pages. Add source lines. Add or improve practice lines. Update `models/` when you learn something about a model.
4. Run `npm run kb:check` (it validates the format, ids, duplicates and evidence links) and `npm run kb:build` (it refreshes `index.json`).
5. Commit with a message that says what you added and from which area.

To correct a record, edit the line and add a note in `notes`; do not delete a source because you disagree, add the disagreement as a practice with `conflicts`.

## How Monofilm uses it

`npm run kb:build` writes `index.json`: every practice with its evidence, grouped by stage. The studio's own prompts and checks are derived from practices whose `monofilm.status` is `done` or `partial`. A practice with status `none` and strength `measured` or `multi-source` is a candidate for the next change: see `playbook/` for the current list.
